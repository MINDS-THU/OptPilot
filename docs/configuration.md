# Configuration reference

The public project format is `optpilot.experiment.yaml`. Print the complete structural schema with `optpilot schema` and validate the manifest, its referenced files, artifact contracts and authored Studies with `optpilot validate optpilot.experiment.yaml`. Schema validation checks structure; project validation also resolves references and prepares each authored Study.

Top-level arrays are `environments`, `tasks`, `instances`, `suites`, `candidates`, `generators`, and `studies`. IDs identify artifacts; editing an artifact retains its ID and creates a new immutable version. Every artifact can declare `files` relative to the manifest. Python entrypoint files are captured automatically; imported helpers and data must be listed.

Task fields include `runner`, `evaluator`, `harborTask`, `decisionContract`, `metrics`, `observations`, `feedbackMetrics`, `parameters`, optional `environment` and `environmentParameters`, and resource requirements. Native Tasks default to trusted local Python. Harbor Tasks use a local Harbor task package; manual Tasks issue human work orders. Instance fields include `task`, `parameters`, grader-only `private` values and optional declared files. Suite `instances` names Instance IDs. A native Grader receives `(candidate, context)` and returns a metric mapping or `{metrics, evidence}`. Program Candidates receive JSON-compatible arguments and return a JSON-compatible value in a separate worker process. `decisionContract.input` validates `{args: [...], kwargs: {...}}`; `output` validates the return value. Private Instance data is supplied to the trusted Grader and is excluded from Generator feedback and saved-version inspection. Core does not prevent Grader code from exposing that data to a Candidate or in reported metrics and evidence.

Study fields include `suiteIds`, `instanceIds`, `candidateIds`, optional `generatorId` and `generationBudget`, `metric`, `direction`, `repetitions`, `seed`, `retries`, `timeoutSeconds`, `resourceBudgets`, and `sshTarget`. `optpilot experiment review --study ID` resolves an authored Study. Selection flags or `--selection FILE` provide the same contract. Review records immutable versions, planned Trial count, selected metric and runner. Subsequent source edits do not change that review. `optpilot experiment run --review REVIEW_ID` starts it; supply the original `--run-id` to resume a waiting or interrupted Run.

For parameter Tasks, a decision schema declares typed fields and optional defaults or bounds. Instance parameters provide the concrete settings for each scored case. A Task may map its parameters to Environment settings with `environmentParameters`. Metrics can be names or objects with a name, description, unit and optimization direction. A Study's selected metric must exist on every selected Task.

Each artifact may declare relative `files`. The Python evaluator or generator entrypoint is captured automatically, but imported helpers and data must be declared. Symlinks, paths outside the project and oversized artifact closures are rejected. Generated program Candidates declare their entrypoint and supporting files in the generator result and are frozen before its temporary workspace is removed.

An Environment can declare an optional `interface` for graphical try-runs from the desktop. Supply a Python script as `entrypoint`, a local page `path` and a health-check `readyPath` (both default to `/`). Only the entrypoint and declared viewer `files` or `filePrefixes` are copied into the session. Prefixes refer to files already frozen by the Environment. The script receives `--context` with the path to a JSON file containing the frozen task and candidate references, public task parameters, seed, and the environment values named in `interface.settings`. Bind to `127.0.0.1` using `OPTPILOT_INTERFACE_PORT`. Task grading code and Instance private data or files are not provided to the viewer.

Set `supportsTrialSettings` only when the viewer can use the same public inputs as the evaluator, including the trial seed. The desktop then offers the original settings for a completed compatible trial. Changes create a custom try-run. A try-run creates no evaluation record. Instances saved as presets can retain a separate `visualSeed`, which does not override the seed used by a Study. The repository example at `catalog/production_agv_scheduling/optpilot.experiment.yaml` declares a working viewer.

The earlier Environment/Method/Study launch CLI is retired. Runtime internals remain covered by regression tests but do not provide a second public workflow.
