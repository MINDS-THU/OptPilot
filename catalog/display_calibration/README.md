# 用 OptPilot 比较两种屏幕校准方案

目标是判断哪套 RGB 增益能让带色偏的屏幕更接近指定灰阶。本项目使用本机模拟色度计，整个流程离线运行。OptPilot 负责评测与试验记录，示例中的 MCP 服务独立检查设备权限、处理预约、返回读数并释放名额。它不需要 API 密钥、LLM、外部网络或真实仪器。

## 在这台 Mac 上体验

1. 双击 **重跑演示.command**，在终端中按提示按回车，依次观察设备发现、名额冲突、恢复和评分。它会生成一份新的评测，更新本目录的 **演示报告.md** 与 **演示结果.json**。以前的 Run 保留在项目关系图中。命令行加 `--auto` 可以连续跑完。
2. 双击 **open_desktop.command** 打开桌面版；首次进入空窗口时点 **Open project**，选择本目录。该启动器使用项目自己的桌面配置和资源台账。
3. 在项目关系图中双击评测，打开 **概览 → 方案评分**。切换到试验结果，展开某个试验的证据，比较 `target` 和 `readings`，再查看设备返回的 `reservation`、`measurement` 和 `release`。
4. 在关系图中单击评测，查看模拟色度计名额的占用或释放状态。点 **查看资源记录** 可追溯每次分配与释放。在 **设置评测** 中选择“两个灰阶”和两个方案，即可启动一次新比较。

从源码或其他 Unix/macOS 环境使用时，请在安装了当前 OptPilot Core 的 Python 中运行 `python demo.py`；`python demo.py --prepare` 只同步仪器并冻结定义。移动项目后应本地重新运行准备步骤，使新的测量连接到移动后的模拟设备数据库。

## 实验里有哪些对象

| OptPilot 对象 | 本例 |
| --- | --- |
| 任务 | 给定灰阶和候选增益，测量屏幕并计算三通道平均绝对误差 |
| 任务实例、实例集 | 暗灰 64、亮灰 192，组成“两个灰阶” |
| 方案 | 原厂增益、根据模拟屏已知偏差预先选定的色偏补偿增益 |
| 评测设计 | 两方案 × 两实例 × 一次重复，误差越小越好；本次并行预算最多 1 个名额 |
| Run / Trial / Attempt | 一次对比是一个 Run。默认有 4 个 Trial，每个成功 Trial 有一次测量 Attempt |
| 实验资源 | 有 2 个物理通道、团队上限 1 个的模拟色度计。设备标识和余量从服务取得 |

## 谁来决定什么

- **服务负责设备事实和授权。** `bench_server.py` 以 MCP stdio 暴露状态和 `reserve`、`measure`、`release`。团队上限预设在模拟服务中。客户端通过 MCP 读取，预约时在设备端事务中重新核验。
- **实验作者负责测量方法。** `optpilot.experiment.yaml` 声明指标、方案、实例、一次测量需要的设备能力，以及本次评测预算。**使用项目的人不需要往资源表手填仪器标识或通道数。**
- **项目适配器负责把两边接起来。** `demo.py` 把服务报告的授权容量和其他使用者的占用同步到本项目台账，再启动或恢复同一个 Run。`grading.py` 核对实际分配，向服务取得预约后才测量。普通桌面评测复用上次同步的供给，设备在每次测量前仍有最终决定权。这个示例展示的是已知接口的适配方式，接入另一种仪器要定义它自己的状态、预约和读数接口。

演示会主动模拟一次同组同事占用。此时还有一个物理通道空闲，但团队名额已用完。你能在报告中看到设备拒绝第二份预约、OptPilot 等待和恢复，以及四条各自独立的测量回执。

## 数据位置

`.demo/workbench.sqlite3` 保存仪器回执，`.demo/registry/` 保存本项目专用的资源台账，`.optpilot/experiments/` 保存版本、运行和原始证据。完整报告中的 `leaseId` 可串起同一次试验的预约、测量和释放。
