OptPilot 0.2.0 is the project's first official Core release: a Python package and CLI for versioned, measured experiments that retains the selected inputs and evidence behind each Run.

{/* truncate */}

## Why a boundary matters

Optimization projects rarely begin from nothing. They already have a simulator, benchmark, solver, policy or agent loop. What tends to be rebuilt is the experiment record that connects authored contracts and concrete cases to frozen submissions, execution attempts and measured results.

The public project model uses Environments, Tasks, Instances, Suites, Candidates, optional Generators and Studies. Reviewing a Study resolves its artifact references to exact immutable versions before execution.

Study review resolves project references to immutable versions. A Run records actual inputs, Trial and Attempt outcomes, scores, failures and evidence in `.optpilot/experiments`.

## What the release executes

Native Tasks support parameter and callable-program Candidates, trusted local Python grading, optional feedback-driven Generators, resource-aware execution, manual work orders and registered POSIX SSH workers. Harbor runs supported agent configurations through local Docker-backed jobs.

Equally important, unsupported combinations fail closed. The public schemas contain room for future capabilities, but the runner does not pretend to execute a path it cannot preserve correctly. The [Executable Capabilities](https://minds-thu.github.io/OptPilot/reference/capabilities/) page is the authoritative matrix.

## Evidence tied to inputs

OptPilot retains frozen versions, actual inputs, Trial and Attempt outcomes, scores, failures and evidence in the project experiment ledger.

This evidence model is the point. A score is useful only when it remains tied to the candidate, task, instance and execution that produced it.

## Desktop is separate

OptPilot Desktop uses the same manifest and experiment ledger as Python Core. Its source is maintained privately in the OptPilot-Desktop repository. Public installer downloads are not available yet.

The local-first design keeps execution visible. Local Python grading runs trusted project code and is not an adversarial sandbox. Harbor provides its own task isolation. Provider credentials stay outside retained Run evidence.

## Research packages as integration tests

The release catalog includes three paper companion packages:

- **DEVS-Gen** packages generated discrete-event simulators with versioned Tasks and Candidates.
- **LLM-Guided Heuristic Design** proposes executable policy Candidates from simulation scores and exact-replay traces.
- **COOPA** produces one solver Candidate from an operations-research problem while retaining the complete solve artifact.

They deliberately exercise different points in the same versioned experiment model, from parameter evaluation to generated policies and one-shot solving.
